Workloads — what request shape to measure

A workload is one kind of request llm-bench sends to the running server and times. You pick the prompt length and how many tokens to generate. A sweep runs every workload for every variant (model × dimensions). The three kinds mirror llama-bench:

  • pp — prefill / prompt processing. The server reads a long prompt (N tokens) and emits just one token. This measures how fast it chews through input — the part that makes the first token wait on a long chat. Reported as Prefill t/s and TTFT (time to first token).
  • tg — token generation / decode. A tiny prompt, then generate N tokens. This measures the steady typing speed you actually watch. Reported as Decode t/s and inter-token latency (ITL).
  • pg — prefill + generate (realistic). A long prompt followed by N generated tokens, like a real request. Captures both phases plus total E2E latency.

Dimensions

The parameters you want to test. Each dimension is swept across all its values and the result is the cross-product (dimension A with 2 values × dimension B with 3 values = 6 variants). Dimensions can be args (command-line flags, appended to the engine command verbatim — so any flag works, even ones that don't exist yet) or env (environment variables set for the engine process).

NameTypeArg template (args only; {v} = value)Values

Arg template: how each value becomes a command-line fragment. Two ways: (1) Leave it empty — the dimension name is used as the flag. E.g. name flash-attn with values on,off,auto becomes --flash-attn on, --flash-attn off, --flash-attn auto. (2) Put surrounding text with {v} for the value, e.g. --n-gpu-layers {v}. To switch between whole flag groups, make the values start with a flag — e.g. values --flash-attn on --no-mmap;--flash-attn off (separated by ;).
Env values: each is a KEY=value pair (a bare KEY means value 1), separated by ; — e.g. name cuda with values CUDA_VISIBLE_DEVICES=0;CUDA_VISIBLE_DEVICES=1. The arg template is ignored for env dimensions.
Values: 1,2,4-8+2 (llama-bench ranges: first-last, +step, *multiplier), literals like on,off,auto, or fragments separated by ; when a value itself contains commas (e.g. --ts 1,2;--ts 3,4).

Results

Tick one or more sweeps to aggregate them together. Prefill/Decode t/s prefer server-reported numbers when the engine provides them (llama.cpp does); TTFT and latency are measured at the HTTP level — i.e. what you actually experience.

Logs

Full server output (stdout + stderr) for every variant of every sweep, in one place. This is where crashes, startup errors, and the engine's per-request timing lines live. Rows are newest first; open a running variant's log and it keeps refreshing while it runs. Use Check on the Engines tab to verify an executable path resolves.

Engines

An engine is just an executable + argument template: llm-bench launches it with the args below (substituting {model} and {port}), then talks to its OpenAI-compatible /v1/completions endpoint. Any server that speaks that dialect works. Use Check to verify the executable is found on this machine.
