Sweeps

Each sweep tries one combination ("variant") of your engine parameters: it launches the server, warms it up, runs timed requests, shuts down, and moves on. Variants run one at a time so only one server ever touches your GPU. Click Variants for per-combination status and engine logs, Results for metrics and exports.

Workloads

What kind of request shape to measure. Same idea as llama-bench's pp/tg/pg tests, but sent over HTTP to the running server. A sweep runs every workload for every variant.

KindPrompt tokensGen tokens

pp (prefill): feed a prompt of N tokens, generate one. Measures how fast the prompt is processed (time-to-first-token).
tg (generation): tiny prompt, generate N tokens. Measures steady-state generation speed.
pg (prompt + generate): realistic chat-shaped request: a prompt of N tokens followed by M generated tokens.

Dimensions

The parameters you want to test. Each dimension is swept across all its values and the result is the cross-product (dimension A with 2 values × dimension B with 3 values = 6 variants). For each value the fragment is appended to the engine command line verbatim, so any flag the engine understands can be swept — including flags that don't exist yet.

NameArg template (optional; {v} = value)Values

Arg template: how each value is turned into a command-line fragment. Three ways: (1) Leave it empty and the dimension name is used as the flag — name numa with values distribute,isolate,numactl becomes --numa distribute, --numa isolate, --numa numactl. (2) Put {v} plus surrounding text, e.g. --threads {v}. (3) Put just {v} to emit the value as-is — for switching between whole flag groups: {v} with values --flash-attn on;--flash-attn off.
Values: 1,2,4-8+2 (llama-bench ranges: first-last, +step, *multiplier), literals like on,off,auto, or fragments separated by ; when a value itself contains commas (e.g. --ts 1,2;--ts 3,4).
Click Preview plan to see the exact command that will run for the first variant before committing to the sweep.

Results

Tick one or more sweeps to aggregate them together. Prefill/Decode t/s prefer server-reported numbers when the engine provides them (llama.cpp does); TTFT and latency are measured at the HTTP level — i.e. what you actually experience.

Engines

An engine is just an executable + argument template: llm-bench launches it with the args below (substituting {model} and {port}), then talks to its OpenAI-compatible /v1/completions endpoint. Any server that speaks that dialect works. Use Check to verify the executable is found on this machine.
